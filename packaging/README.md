# Distribution builds

`publisher.json` describes the three executable surfaces, supported runtime identifiers and native package formats. `ArgueBot.Publisher` builds the service, CLI and TUI together as self-contained single-file executables, includes the dashboard and dependency/license inventory, and writes artifacts and `SHA256SUMS` under `installers/<current-build-version>/`. It never changes the product version or publishes an artifact.

Build the dashboard first, then use `build-installers.sh --runtime osx-arm64` on macOS, `build-installers.sh --runtime linux-x64` on Linux, or `build-installers.bat --runtime win-x64` on Windows. The wrappers use the same publisher as the native CI matrix. For one format:

```sh
dotnet run --project src/ArgueBot.Publisher -c Release -f net10.0 -- --runtime osx-arm64 --channel archive
```

The archive channel can cross-compile all six listed runtimes. Native channels require their corresponding OS: Inno Setup on Windows, `pkgbuild` and ad-hoc `codesign` on macOS, and fpm/AppImage tools on Linux. CI installs its own tools. Local Linux builds need Ruby, development tools, rpm, file, squashfs-tools and desktop-file-utils, followed by `gem install --no-document fpm -v 1.17.0`. `node scripts/install-package-tools.mjs linux-x64` downloads checksum-pinned AppImage tooling and prints the variables to set. On Windows, the same script with `win-x64` installs the pinned Inno compiler into `.run/package-tools/inno`; add that directory to PATH. AppImage uses a pinned runtime instead of downloading a moving latest runtime while packaging. Native packages build in fresh staging directories, so a failed rebuild does not replace the previous artifact.

Add `--doctor` to check a channel without building it. Packaging selects the exact SDK version in `global.json` in an isolated working directory; ordinary development keeps its existing SDK roll-forward policy. A newer SDK can change implicit linker dependencies and cannot silently bypass reviewed packaging locks. The doctor reports the required version and missing native tools before any publish work starts.

Normal development dependency locks remain in each project. Packaging locks live under `packaging/locks/<runtime>/` because single-file and runtime-specific restore graphs differ. The publisher requires those files and uses locked restore. To intentionally refresh a packaging lock after reviewing dependency changes, restore each of the Server, Cli and Tui projects with matching `-r RID`, `-p:ArgueBotPackaging=true`, `-p:ArgueBotPackageRuntime=RID`, `-p:TargetFrameworks=net10.0`, `-p:PublishSingleFile=true` and `-p:IncludeNativeLibrariesForSelfExtract=true`, then review the generated lock changes. This is a dependency update, not a routine build step.

Extract an archive into an isolated directory and run `node scripts/test-packaged.mjs PATH`. It tests native startup, sibling-service discovery, dashboard assets, SQLite persistence, Unicode paths and service restart using a disposable workspace. macOS app bundles additionally test their browser launcher through an isolated `open` fixture. A cross-compiled archive is labeled built until it has run on a matching platform. The CI matrix prints architecture mismatches explicitly.

The software is not signed with a purchased certificate. macOS executable bundles receive free ad-hoc signatures and are not notarized; Windows packages are unsigned. Review the source and checksum before proceeding through an operating-system warning. Windows offers **More info > Run anyway**; macOS offers **Privacy & Security > Open Anyway**. `UNSIGNED.txt` is included in every payload and shown by the Windows installer.

Linux packages provide `arguebot`, `arguebot-tui`, `arguebot-server` and `arguebot-web`, plus terminal/browser desktop entries. The browser launcher requires `xdg-open` and an available graphical session. AppImage opens the TUI with no arguments; use `--web` for the browser or pass CLI arguments such as `--help`. Set `APPIMAGE_EXTRACT_AND_RUN=1` on systems without FUSE. Windows Start Menu entries open the terminal or browser. The macOS app opens the browser. All browser launchers start or attach to the selected workspace and open its loopback dashboard URL.

The Linux packages include a per-user systemd unit, enabled with `systemctl --user enable --now arguebot.service` if startup at login is desired. Windows offers an explicit startup task during installation. Otherwise, opening the TUI or web launcher starts or attaches to the workspace on demand. Uninstalling application files must preserve the selected workspace and its protected credential keys.

Run `node scripts/test-linux-installer.mjs PATH_TO_PACKAGE` on an isolated Linux host with package-manager privileges to test installation, same-version replacement and removal. It validates desktop entries, runs the packaged lifecycle checks and verifies that uninstall leaves the database unchanged. It refuses an existing application. The RPM fixture uses `--nodeps` to permit execution in the Ubuntu test container; this is not Fedora dependency-resolution evidence. The macOS check executes the expanded package payload and verifies its ad-hoc signature, not a system-wide installer transaction. Windows native execution, upgrades from a published prior package, package-manager publication and hosted CI results remain open acceptance gates in the original plan.
