# Complete-service recovery is a protected global resource

Status: accepted implementation decision, October 19, 2026.

A complete-service archive contains data from every tenant, global configuration and, when explicitly requested, the local encryption key ring. Giving a tenant administrator access would cross the structural tenancy boundary. Backup records and their operation records are therefore protected global resources, alongside schema bookkeeping and built-in roles. Only an authenticated system administrator may enumerate, create, inspect, download, verify, restore or delete them. Initiating tenant/user identifiers are accounting fields, not ownership grants. A tenant administrator's role name never grants global backup access.

The service creates portable relational snapshots in a consistent database transaction. An archive includes a strict file inventory, SHA-256 checksums, schema/provider/application provenance and exact dependency references. Default archives omit session keys and literal database connection configuration; environment credential values are never resolved into archives. Secret-inclusive archives require an explicit passphrase. The encryption envelope uses bounded AES-256-GCM frames, PBKDF2-SHA256 with a fresh salt, frame position authentication and an authenticated terminal frame. Output is staged until all archive and snapshot checks succeed. Unencrypted checksums detect accidental corruption; they do not establish a trusted archive author.

Recovery jobs are bounded service-owned work. Their status and safe failure codes persist; passphrases do not. Service restart marks uncertain jobs failed instead of replaying them. A passphrase remains in managed memory while its accepted operation runs; immutable managed strings cannot promise deterministic memory erasure. Decrypted staging files and archive files receive current-owner permissions and temporary staging is removed on completion or failure.

Controlled HTTP restore publishes a new home beneath the source home's restores directory. SQLite creates a new file. PostgreSQL uses an explicitly provisioned empty database through a service-machine environment reference. Neither path overwrites an existing home, replaces the active database or starts recovered workers. Source settings and the portable snapshot remain available for review; restored sessions are revoked and uncertain work is reconciled. PostgreSQL commit and filesystem publication are separate resources: a post-commit failure retains protected staging and records its path. An incomplete-recovery marker prevents startup until operator reconciliation. Recovery never automatically drops a database to retry a failed operation. See docs/RECOVERY.md for the required operator boundary.

Schema migration 4 stores artifact metadata, durable operations and missing credential names in separate relational tables. Restored metadata for external archive files is marked unavailable, because the bundle does not recursively contain historical archives. Queued/running restored jobs become failed. Tests cover tenant-administrator denial, interrupted-job reconciliation, Unicode metadata paging, authenticated binary download, wrong passphrases, tampering, traversal, corrupt snapshot refusal, transactional rollback and isolated-home restoration.

Migration 5 separates system administrator and tenant administrator flags from display/compatibility role names. Existing `admin` roles migrate to tenant administration; only the reserved local owner receives the seeded system flag. Historical snapshot validation uses the column inventory declared by its captured schema, and restored older data is migrated before sessions are issued. A role name alone cannot grant global archive access.

Schema migration 7 persists restore provider, connection reference and retained staging independently from passphrases. Local attachment also binds to a private per-home key and normalized path, with challenge proofs tied to the actual listener port. These process proofs do not replace user authentication. CLI session reuse is owner-protected, endpoint/home scoped and revalidated against current server privileges; it avoids exhausting enrollment limits during frequent commands.
