# Authentication cryptography

The local service issues one-hour opaque sessions encrypted with AES-256-GCM. Every token has a new random nonce. Typed claims contain only platform identifiers and timestamps, and validation also checks the persisted session digest and the current active user/tenant. GCM authenticates ciphertext; modified claims are rejected. Keys live in owner-readable `keys/` files outside the database. Rotation changes the issuing key while retaining old keys for unexpired sessions. A database backup alone cannot reproduce the key ring.

The initial local pairing flow is restricted to the loopback host and an explicit origin allowlist. Pairing codes rotate after each successful use, and pairing attempts are rate limited. Full hosted authentication is a separate, still-open gate. Password-equivalent headers will not be enabled over plaintext HTTP.

The family authentication reference defines SHA-256 password-equivalent login material. Its wire representation can remain stable while persisted verifiers use salted key derivation. Before enabling password login, derive a verifier from the provided SHA-256 equivalent with a random salt and at least 600,000 PBKDF2-HMAC-SHA256 iterations. Do not retain the raw password-equivalent hash as a reusable secret. Make the iteration count configurable with a validated minimum, store it with the verifier, and compare derived values in constant time.

Sources checked October 19, 2026: [OWASP password storage](https://cheatsheetseries.owasp.org/cheatsheets/Password_Storage_Cheat_Sheet.html) and [the .NET Pbkdf2 API](https://learn.microsoft.com/en-us/dotnet/api/system.security.cryptography.rfc2898derivebytes.pbkdf2?view=net-10.0). Password login, credential signatures, role assignments and hosted TLS remain unimplemented until their own code and negative tests are present; this ADR is not evidence they work.

The local listener accepts enrolled sessions in Bearer or x-token carriers, permitting both only when identical. Duplicate/empty carriers and conflicting tenant hints fail closed; x-tenant-guid and x-tenant-id must agree with the resolved tenant. Other credential schemes are rejected even alongside a valid session while their implementations remain disabled. Request principals expose their validated session identifier and carrier, never token material. Session issuance/revocation have transactional audit records; HTTP 401/403 accounting operates independently of request capture. Scoped audit inspection has no HTTP update/delete surface. Database administrators remain outside application-level immutability.
