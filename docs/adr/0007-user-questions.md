# Agents ask the user through held, then parked, questions

Status: accepted November 9, 2026 for v2.3.0; implementation tracked in [PROMPTING_THE_USER_PLAN.md](../PROMPTING_THE_USER_PLAN.md).

Agents in protocol 2 runs ask the person running the debate structured questions through an `ask_user` tool. One request carries one to four questions, each free text, single choice, multi-select or yes/no. The person answers in a modal dialog in the dashboard or TUI, or through the CLI, REST API or C# client. The tool replaces `request_clarification`, whose free-text request returned at once, paused the run only after the turn ended, and needed a manual Resume after the answer. Version 2.3.0 migrates clarification rows into question requests and removes the old tool, route, request fields and table.

A waiting `ask_user` call is first *held*: the tool call stays open for up to `questionHoldSeconds` (default 300) and returns the answer as its result, so the agent keeps the reasoning it was doing when it asked. While a call is held, the invocation deadline stops, the run releases its capacity slot and the time is excluded from the wall-clock budget. When the hold window ends, the person chooses **Answer later**, the run is paused or the service restarts, the request is *parked*. The tool tells the model to end its turn without conclusions that depend on the answer, and the attempt ends as `awaiting_input` with no vote, proposal or speaker advance. Once the answer arrives, a resume attempt repeats the same step with the stored tool history and the answer as the `ask_user` result. REST models and envelope CLIs replay their continuation exactly. Claude Code and Codex use native session resume where their versions support it and otherwise get a reconstructed context containing the draft, the question and the answer.

We rejected three alternatives. Always parking would make every answer cost a second invocation and lose the agent's working state even when the person answers within seconds. Always holding would keep CLI processes and capacity slots alive for hours and would not survive a restart. A pre-debate form alone would not cover questions that only arise once the panel has started. The optional intake step (`intake: ask_if_needed`, the default for new debates) covers the vague-request case at the start, and `ask_user` covers the rest.

Answers are moderator context. By default every seat sees them; a request can limit an answer to the asking seat. The first resolution wins, and later attempts get 409 `question_already_resolved`. Question text is model output and every surface renders it as data, never as interface chrome. Agents are told never to ask for secrets, and answer forms warn against pasting them.
